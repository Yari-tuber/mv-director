# 审片：check.py 量什么、没过怎么改

check.py 不看你的代码，只看渲出来的视频：把画面缩成 160×90 灰度，算每一帧和上一帧差多少（画面变化量），再和 song.json 的拍子对。

| 项目 | 怎么量 | 门槛 | 没过怎么改 |
|---|---|---|---|
| 小节头命中率 | 小节头那一下（之后 0.1 秒内）的画面变化，是不是前面 0.4 秒的 2 倍以上 | ≥ 70% | 每个小节头都安排一个看得见的动作：换镜头、`rules: bar → punch`、换颜色、加元素、字砸下来。镜头里一直匀速在动的话，小节头那一下就显不出来：平时动得慢一点，小节头动得猛一点 |
| 拍点命中率 | 每一拍（≥1.6 倍） | 参考（副歌最好 ≥ 50%） | `M.pulse('beat')` / `M.pulse('kick')` 驱动主体，不要只驱动背景 |
| 大时刻 | 画面变化 ≥ 前面 4 倍，或者亮度突变 ≥ 0.12 | 全部 ✓ | 那一拍要换镜头（smash / flash）+ 画面本身变（尺度、颜色世界、母题变形）+ 特效。前面 0.5 秒要收（变暗、变慢、定格），反差才出得来 |
| 死画面 | 连续 1 秒以上几乎不动 | 0 处 | 加呼吸：慢推（`cam`、`drift`）、母题微动、背景纹理流动；抽鼓的定格也别超过 1 秒 |
| 起伏 | 画面变化（按小节平均）和 arc 的相关 | ≥ 0.4 | arc 低的段落：少切、慢推、颜色少；arc 高的段落：快切、大动作。看每段那张表，副歌要最大 |
| 硬切在拍上 | 亮度分布突变的帧离最近的拍多远 | ≥ 80% 在 ±1.5 帧内 | 切点写 `bar9` 这种；转场的正中间就是 at；画面里自己做的突变也要卡 `M.pulse` 的时刻 |
| 歌词上屏 | 每句唱的时候，屏幕上有这句的时间比例（读 textlog） | 每句 ≥ 75% | 检查这句的 mode、颜色是不是和背景一样、是不是被画面挡住；自己画的歌词要 `M.logLyric` |
| 字号 | 每句最大字号 | ≥ 100px | `size: big` 起步，金句 `hero` |

## 看图（数字过了也要看）

- `out/审片_运动曲线*.png`：白线是每小节平均运动，黄线是歌的能量，红竖线是小节头，星星是大时刻（黄 = 炸了，红 = 没炸）。好的片子：白线有明显的谷和峰，峰在副歌；红竖线处有尖刺。
- `out/stills/审片_大时刻*.jpg`：每行一个大时刻，-0.2 秒和 +0.05 秒两张应该判若两图。
- `render.py bars`：每小节一张。连着 4 张以上看着差不多 = 观众会无聊。

## 三轮还过不了

回到立意：多半是点子没有升级空间（母题从头到尾一个样），或者主歌太满、副歌没有反差。改 plan.md 和 cues.json，不要只调特效参数。
